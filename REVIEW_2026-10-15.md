# Critical project review — 2026-10-15

Five questions were asked: implementation errors vs the original, whether the
metrics are the right ones, the comparison to the original results, the
paper's register, and one consolidated path to production. Findings were
produced by three independent review passes (method audit against the PDFs in
`docs/`, metrics audit, manuscript read) and the load-bearing claims were
re-checked by hand against the code and result files.

## 1. Implementation errors relative to Fang & Gough 2013

Three genuine divergences that change results, ranked. None of them is in
`RELATIVE_INFERENCE_REPORT.md` or `TODO.md`.

### 1.1 The h-score is not the paper's h-score

The paper defines the h-score as a hypergeometric **z-score**,
(observed − expected) / sd, and says it introduced it because FDR-based
scores "collapse" for the top predictions (BMC Bioinf 2013, p. 5 and p. 9).

`run_dcgo_human.py:262-330` (`calculate_hypergeometric_score`) computes
`hypergeom.sf` (the same one-sided p-value again), then
`min(100, max(1, -log10(p) * 10))`. It is a monotone transform of the
p-value that saturates at p ≤ 1e-10. `validation/temporal_benchmark.py:609`
already notes ~37% of significant associations sit at exactly 100 and
switches to −log10(p) for that reason. So the code reproduces the defect
the paper introduced the h-score to fix, and `min(overall, relative)` at
`run_dcgo_human.py:1557-1580` is redundant with `max(p)`.

Effect: every ranking and every transfer score downstream uses a p-value, not
the paper's effect-size-like score. Fix is small: compute z from the
hypergeometric mean and variance, take min over overall/relative, rescale.

### 1.2 The p-score transfer double-counts inside one domain

The paper: each domain contributes **one** score per term (max h-score over
the domain's descendants of that term, via output propagation), then scores
are summed **across** the target's domains and supra-domains, then min-max
scaled per target (p. 9).

`validation/temporal_benchmark.py:251-283` (`transfer_predictions_pscore`)
loops `for term in (go, *ancestors): sums[term] += s` for every association
of every domain. A domain with k significant descendants of term T adds
k·s to T. General terms are inflated in proportion to how many specific
descendants a domain carries. The input is also the direct significant table
with −log10(p), not the propagated profile with h-scores.

Effect: this is the transfer step every §2 and §4 protein-centric number
passes through. It favours generic terms, which is exactly the pattern the
IC floor was introduced to counter.

### 1.3 InterPro-keyed supra-domains are not "successive domains"

The paper's supra-domain is a run of successive, non-overlapping SCOP domains
in a SUPERFAMILY architecture, excluded when it spans unassigned sequence
(BMC p. 8; NAR 2013 D539).

`src/domain_annotation_parser.py:321-374` sorts protein2ipr rows by start
and joins every window of 2–3 **rows**: no overlap check, no dedup, no gap
rule, no recurrence requirement. Nested and overlapping InterPro entries
(family + domain + site entries over the same residues, PRINTS fingerprints
split into several rows) become "adjacent".

Measured on `results/domain_go_associations_significant.tsv`:

| supra associations | with a repeated constituent (IPRx,IPRx or IPRx,IPRy,IPRx) |
|---:|---:|
| 121,234 | 48,424 (40%) |

Effect: a large share of the supra BH family is single domains re-tested
under a second name. It inflates the hypothesis count, the "emergent
combination" counts, and the surprise-score input. The `--domain-key ssf`
path avoids the nesting but still has no gap handling.

### 1.4 Known, documented gaps (not errors, but not the paper's model)

- Paper always runs input propagation and the relative test; both are
  opt-in here, and the default run is not the paper's model.
- FDR 0.01 vs the paper's 1e-3; BH split into single/supra families (paper
  silent); BP/MF/CC pooled.
- Relative background: the paper contradicts itself (all parents in Methods,
  any parent in the Fig. 1 caption). The pipeline uses the union. But
  `validation/apply_relative_inference.py` uses the **intersection** with
  alpha = 0.05 as a post-hoc filter. That script produced the only
  domain-centric evidence that relative inference helps (ledger row B8,
  precision 0.218 → 0.253). That number is from a different test than the
  pipeline runs.
- `--min-ic` strips floored ancestors from the propagated file, so the output
  is no longer a complete true-path profile.
- Evidence filter `manual` keeps `ND` (root-only "no data") annotations.
- Max supra length 3; the paper has no cap.

## 2. Are the metrics right?

Verdict: the evaluator is now correct (CAFA-evaluator cross-check, PR #74),
but it measures the wrong thing for the decision being made. The ablation's
yardstick is protein-centric F_max/AUPRC after a per-protein min-max
transfer. That tests the transfer heuristic and the cohort's coverage more
than it tests the association inference.

Specific problems:

1. **Coverage dominates.** `validation/ablation_pr_decomposition.tsv` shows
   about half the no-knowledge cohort gets no prediction from any rung
   (`coverage_any` ≈ 0.49–0.57). Recall is capped there. Naive covers 100%.
   The no-knowledge gate selects for proteins whose domains had no
   associations at t0, the hard tail for a domain method.
2. **Min-max scaling erases absolute strength.** A protein with one
   surviving association scores 1.0 on every term. The relative test's whole
   output is "fewer, stronger associations", and its strength signal is
   erased before scoring. The relative rungs' best F_max threshold is
   τ = 0.0 in most cells, i.e. "predict everything that transferred". So
   the comparison is "pruning by parental test" versus "pruning by the best
   q cutoff chosen on the test set". Base gets a test-set-tuned threshold;
   relative gets none. That alone can produce "relative loses on both axes".
3. **Supra-domains cannot show up in a protein-centric metric.** A supra
   association rarely changes a protein's ranked term list, because the
   constituent domains already carry most terms. The ablation's "little
   protein-centric effect" is uninformative, not negative. TODO.md reads it
   as negative.
4. **The sensitivity/PPV decomposition is at the wrong operating point.**
   Reading each configuration at its own F_max compares different places on
   different curves. Fixed-sensitivity PPV (at Base+relative's sensitivity,
   what PPV does Base reach by q-threshold alone?) is the one question that
   separates the two.
5. **Metric-chasing is documented in the repo itself.** F_max was chosen as
   headline after both metrics were seen (VALIDATION_PLAN "Where §2
   landed"); the p-score transfer became default because it lifted the
   headline split and is now baked into every ablation rung; `--min-ic 1`
   was chosen from an in-sample sweep and never appears in the ablation
   (floors 0/2/4). "N of 9 cells" tallies three nested cohorts as nine
   votes, and two convention choices each flip a decisive cell.
6. **AUPRC** is a weak secondary here: the (0,0) anchor is worth up to 0.13
   for naive and 0.03 for a rung, the same order as most rung contrasts.

What the guiding metric should be:

- **For choosing the production configuration: association-level and
  temporal.** Train on t0, score (domain, term) pairs against curated pairs
  **added** to InterPro2GO between InterPro 85.0 and current. The dated file
  is already on disk at `data/raw/interpro_archive/85.0/interpro2go` and
  has never been used. Report precision at matched association count per
  rung, bootstrapped over **domains**, not proteins. Add
  `validation/temporal_surprise.py` per rung for supra-domains, which
  InterPro2GO cannot see.
- **For the paper: two claims, two instruments.** "The associations are
  good" → domain-centric temporal precision plus emergence enrichment. "The
  associations transfer to proteins" → CAFA F_max with CAFA-evaluator
  conventions and IA-weighted S_min, on one pre-specified configuration, on
  an untouched interval, with naive restricted to covered proteins.
- **Minimal change to the ablation, no new runs:** add fixed-sensitivity PPV
  and fixed-budget F per rung from the existing panel curves; add the
  association-level temporal precision per rung; stop tallying 9 cells and
  pre-specify BP and MF at IC≥2 as the decision cells.

Note that §1.2 above means the protein-centric numbers should be regenerated
after the transfer fix before any of this is re-read.

## 3. Comparison to the original results

Done once (VALIDATION_PLAN §3.1, 2026-08-04), on the `--domain-key ssf`
keying, against what they *shipped*, split direct vs inherited. Precision
0.54–0.63 on the shared SCOP-superfamily space. Recall is not interpretable:
69% of their pairs we miss have zero co-occurring human proteins, and only
36% of their domains are reachable (InterPro has no SCOP family level).
Their table also carries 20% rows with `all_score = 1.0`, the SQL default,
so a rank correlation against their FDR is capped.

Downloadability, checked today:

| file | local copy | server today |
|---|---|---|
| `Domain2GO.sql.gz` | yes, sha256 pinned, 2026-08-04 | responds (slow, ~15 s) |
| `SP2GO.txt` (92 MB) | yes, sha256 pinned | timed out at 60 s |
| `Domain2GO_supported_only_by_all.txt` | yes, sha256 pinned | not probed |
| `supfam.org/SUPERFAMILY/dcGO/` page | n/a | timed out |

supfam.org itself answers. The large files are on a slow or flaky host.
The three reference files are safe on disk under `data/raw/dcgo_reference/`
with checksums in `config/settings.py`. They should go into the archived
release so the comparison does not depend on that server.

What the comparison does not yet do: it has not been rerun on the
paper-parity configuration, the relative-inference question is not tested
against their output, and the EC/keyword/disease tables are untested.

## 4. Paper register

Verdict: not casual in the slang sense. It is a confessional, argumentative
drafting voice, with heavy internal bookkeeping in the main text. Journals
expect flat declarative reporting with interpretation confined to
Discussion. Roughly half the length should go.

Patterns, each with an example:

- Editorialising: "The honest conclusion is that…", "Read plainly, this
  table says three things", "This is the strongest evidence in this paper".
- Flourish: title "what its predictions are worth"; "the original dcGO's
  central trick"; "the floor's job is killing vacuous terms"; "escape hatch".
- Process narrative: "a figure we could trace only to project
  documentation"; defect histories for shrinkage, species, regulates edges,
  four fixed bugs.
- Bold for emphasis: "but **loses** for molecular function".
- Scaffolding in prose: `[C2a]` tags on nearly every sentence, PROVISIONAL
  and era banners, CLI flag names, PR numbers, `VALIDATION_PLAN.md (item 2)`.
- §7 "Open questions for the authors" with struck-through items. Item 16
  says the dcGO PDFs could not be read, which is false and a drafting
  artefact.
- One-paragraph ~330-word abstract; sentences over 90 words with em-dash
  chains.

Structure: §3.4 is missing but cross-referenced twice; Results carries the
Discussion; Limitations (20 items) is longer than Discussion; no figures;
8 references. Internal contradictions: Limitations item 7 says no comparison
to original dcGO exists, §4 reports it; vocabulary counts drift (33/28/35).

Highest-value edits, in order: regenerate the provisional blocks and strip
all tags and banners; delete §7 and the defect histories; move interpretation
out of Results; de-voice (no "honest", "plainly", "trick", "killing",
bold-for-emphasis); replace flag names with method names and add the p-score
and surprise formulas; rewrite the abstract to ≤300 words; add a pipeline
figure and PR curves; expand references to ~30.

## 5. Consolidated path to production

"Production" here means three deliverables: a frozen configuration, a
reproducible released association set with a DOI, and the paper. Everything
below is gated; nothing later should start before its gate.

### Phase A — fix the method (blocks everything)

1. Implement the paper's h-score (z-score, min over overall/relative,
   rescale 1–100). Export both it and −log10(p). (§1.1)
2. Fix the p-score transfer: one score per domain per term (max over the
   domain's propagated profile), sum across domains, then min-max. (§1.2)
3. Fix supra-domain construction: drop repeated constituents, de-overlap
   nested entries, decide a gap rule, record the rule in the manifest. (§1.3)
4. Make the paper's model the default run, or name the current default
   "baseline" everywhere: input propagation + relative test on. Decide
   FDR 1e-3 vs 0.01 and record why.
5. Drop `ND` from the `manual` evidence filter.
6. Retire `validation/apply_relative_inference.py` and ledger row B8.

### Phase B — fix the evaluation (blocks any decision)

7. Add the association-level temporal metric: precision at fixed budget
   against InterPro2GO pairs added between 85.0 and current, bootstrapped
   over domains. Add `temporal_surprise.py` enrichment per rung.
8. Add fixed-sensitivity PPV and fixed-budget F to the decomposition.
9. Adopt CAFA-evaluator conventions (τ ≥ 0.001, no AUPRC anchor,
   IA-weighted S_min). Score naive on covered proteins as well.
10. Apply PR #74's two evaluator fixes to `temporal_benchmark.py`'s driver.
11. Write the pre-registration into TODO.md before running anything:
    primary = association-level temporal precision, BP+MF; secondary =
    F_max at IC≥2 with CAFA conventions; decision cells named; transfer rule
    and IC floor to be fixed on the development interval.

### Phase C — rerun and decide (one pass)

12. Rerun the nine-rung ablation on t0 InterPro 85.0 with A and B in place.
13. Pick the production configuration from the pre-registered primary.
    Supra-domains are judged by the association-level metric, not F_max.
14. Decide the HPO collapse (996 → 38) on the same evidence.

### Phase D — untouched evaluation (once)

15. Nested split for development (GOA 205 → 215), then one scoring on a
    later untouched interval, or the mouse axis rescored with the fixed
    evaluator and t0 InterPro. Never rerun after reading it.

### Phase E — release

16. Rerun the production matrix on the frozen configuration (gene/UniRef50
    collapse first for model-organism and all-species cells, or drop their
    claims). Regenerate `results/final/`.
17. Pin every input to an immutable release with checksums, including the
    three dcGO reference files. One-command clean-checkout reproduction.
18. Archive snapshots, outputs, manifests with a DOI. Changelog and version.
19. Rerun the original-dcGO comparison on the frozen configuration.

### Phase F — paper

20. Regenerate every provisional block from the frozen run. Then the §4
    edit list. Then a cold read by someone who has not seen the repo.
